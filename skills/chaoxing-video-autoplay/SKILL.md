# 超星视频联播

用于用户明确要求处理已打开的超星课程视频时。目标是只完成平台明确标记为未完成的视频，并保持现有浏览器标签页内的连续播放。

## 不可违背的约束

- 只使用用户已经打开的课程标签页；不要新建课程窗口或标签页。
- 只播放课程目录或当前章节明确显示为未完成的任务点；不要根据猜测的章节编号、连续 ID 或“下一节”顺序推断漏项。
- 已显示“任务点已完成”的视频不得重播。若旧扩展误打开已完成视频，立即暂停并回到课程目录。
- 视频播放速度保持 2 倍速。不要修改平台记录、伪造播放事件、绕过验证码、作业、考试或其他非视频任务。
- 遇到作业、AI 场景题、考试、验证码、登录失效、安全提示或需要人工确认的非视频内容，停止自动操作并通知用户。

## 标准流程

1. 先读取课程目录的实际完成计数（例如“已完成任务点: 40/41”），再从目录真实链接识别带未完成标记的项目。若当前章节页与目录信息冲突，以目录为准并返回目录核对。
2. 通过目录中的实际链接打开目标项目。不要构造或猜测 `chapterId`；章节 ID 可能变更，猜错会触发无权限页或打开错误章节。
3. 进入章节后确认三件事：页面显示“任务点未完成”、播放器存在且正在播放、播放器速度显示为 `2x`。只有这三项成立才允许继续自动播放。
4. 使用静音自动播放或页面已有播放状态维持进度。播放失败时只做有限次数的页面内恢复，不建立高频无限轮询。
5. 将“视频播放到末尾”与“任务点完成”分开判断。视频的 `ended` 事件本身不是跳转许可；必须等平台显示“任务点已完成”或“已完成任务点”，并看到播放器进入“重播”等终止状态后，才允许进入下一节。
6. 如果超星弹出“继续当前节/跳到下一节”之类确认框，而当前任务点尚未被平台确认完成，选择留在当前节；不要点“下一节”。等待平台确认，必要时提示用户人工处理。
7. 平台确认完成后，才允许点击“下一节”。跳转后重新读取当前章节 key、任务状态和播放器，不复用上一节的结束事件或 DOM 节点状态。
8. 如果发生漏跳或误跳：暂停当前已完成视频，返回课程目录；重新读取完成计数和未完成标记；按目录链接补播漏项。不要通过连续点击“下一节”追赶进度。

## 监测与修复

- 健康检查应核对当前标题、任务状态、播放/暂停按钮、当前时间是否增长和速度是否为 2x。
- 只有在发现停止、卡住、结束未跳转或扩展失效时，才在现有窗口重新加载未打包扩展并刷新课程页。
- 每分钟心跳只作为保底；状态正常时保持静默。修复、完成、失败或需要人工操作时才通知用户。
- 扩展自身使用章节 key 隔离事件，防止 SPA 换节时旧视频的 `ended`/`timeupdate` 事件跳过新章节；完成检查应采用有界重试。
- 课程目录显示全部视频任务点完成后，停止心跳自动化，避免重新操作已完成项目。

## 交付与安全边界

向用户报告时说明：已核对的完成计数、正在处理的章节、速度、是否修复扩展，以及是否仍需等待。不要声称“全部完成”，除非目录计数或每个剩余任务点均已得到平台确认。
